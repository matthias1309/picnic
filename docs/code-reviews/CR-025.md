## Findings

| # | Severity | File / Line | Description |
|---|----------|-------------|-------------|
| 1 | minor | `backend/schema_check.py` (`check_schema_drift`) | A missing `NOT NULL` column with no `server_default` compiles to e.g. `ALTER TABLE t ADD COLUMN q INTEGER NOT NULL`. Confirmed against real SQLite 3.53: this statement fails on a non-empty table (`Cannot add a NOT NULL column with default value NULL`), though it succeeds on an empty one. No model in this codebase hits this today — every current nullable=False column either has a `server_default` or only appears on tables created at `init_db()` time — but a future model change could produce a statement the tool reports as "the fix" that isn't directly runnable. Not a blocker: the tool is explicitly detect-and-report, a human is expected to review the statement before running it (REQ-025's own stated design), and the missing column name/table are still correct. Worth a one-line note in ARCH-025's Out of Scope or a future REQ if it's ever hit in practice. |

No major or blocker findings.
