## Summary

primitives (`Card`, `Button`, `ToggleGroup`, `SectionHeader`), plus the

`src/components/ui/*`. Changed: every component's `className` and wrapping
markup. Unchanged: all data flow, all routes, all API calls, every German
string from REQ-020.

Suite: 67 frontend tests pass (was 58). `tsc -b`, ESLint, Prettier clean;
production build succeeds.

## Findings

| # | Severity | File / Line | Description |
|---|----------|-------------|-------------|
| 1 | major | `Budget.test.tsx`, `BudgetHistory.test.tsx` | **Fixed before the rename.** Four existing assertions tested the budget state with `className).toContain("red")`. Renaming the tint to `bg-negative-50` would have made the two negative assertions pass vacuously — testing nothing while still looking green. All four now assert a `data-state` of `"over"` / `"within"`, a signal that survives any future palette change. TEST-022 records this as the one sanctioned edit to existing tests. |
| 2 | major | `BudgetStatusCard.tsx` | **Caught by TC-017-03/04 during implementation.** The first compact history card dropped the "Verbleibend: …" / "… über Budget" line, keeping only month, amounts and bar. That is a REQ-017 content requirement, not decoration — the card was fixed to keep the line rather than the tests relaxed. |
| 3 | major | `PriceHistory.tsx` | **Caught by TC-020-06 during implementation.** A first pass restyled the min/max/Ø summary into a `<dl>`, splitting "Min. 0,99 €" across `<dt>` and `<dd>` so the text match no longer found it. Reverted to single text nodes. Worth recording: it is exactly the kind of "harmless" markup change a restyle invites, and it would have broken screen-reader phrasing too. |
| 4 | minor | `lib/chart-theme.ts` | The only source file containing hex literals, verified by grep over `src/`. Deliberate: Recharts takes colours as props, not class names, so the tokens are mirrored here with a comment pointing back at `tailwind.config.js`. The two values must be kept in sync by hand — the one manual link in the token system. TC-022-06 enforces that no hex leaks back into the chart components themselves. |
| 5 | minor | `Card.tsx` | Extended to forward native `div` props so `BudgetStatusCard` can pass `data-state` on the same element that carries `data-testid`. Mirrors `Button`'s prop-forwarding, so the two primitives behave consistently. |
| 6 | nit | `ProductCombobox.tsx` | The suggestion panel's z-index was raised to `z-30` because the header is now `sticky z-20`. Not cosmetic — at the old `z-10` the panel rendered behind the header when the page was scrolled. |
| 7 | nit | build | Bundle is 879 kB (253 kB gzipped), over Vite's 500 kB warning. Pre-existing and dominated by Recharts; this change adds no dependency and roughly 3 kB of CSS. Out of scope, worth its own REQ if it ever matters on a slow connection. |

No blockers.

### Notes

**Verified explicitly during review:**

- **AC-022-02 / AC-022-03:** `grep -rl '#[0-9a-fA-F]\{3,8\}' frontend/src`
  returns exactly one file, `lib/chart-theme.ts`. No component carries a hex.
- **AC-022-11:** the 58 tests from REQ-021 still pass, and the only existing
  assertions edited are the four in Finding 1. Every German string, every
  `data-testid`, every role and `aria-*` attribute is unchanged — findings 2
  and 3 are the proof the gate works rather than exceptions to it.
- **AC-022-04:** `Button` forwards native props (TC-022-01), which matters
  concretely — receipt deletion passes `disabled={deleteReceipt.isPending}`
  and the login form passes `type="submit"`. A wrapper that swallowed those
  would break both in ways a visual pass would not catch.
- **AC-022-05:** the duplicated toggle markup is gone from both chart
  components; `ToggleGroup` is generic over its value type, so `PriceHistory`
  keeps `PriceHistoryRange` and `PurchaseStats` keeps `SpendingGranularity`
  with no widening to `string`.

**AC-022-08 (responsive) — partially verified, stated plainly:**

Checked in a real browser at 375×812: the login screen has
`scrollWidth === clientWidth` (no horizontal overflow) and the navigation
stays reachable, with the "Picnic" wordmark correctly hidden below `sm`.

The three authenticated pages (Übersicht, Statistiken, Kassenbons) could
**not** be checked in the browser, because reaching them requires entering
credentials, which the reviewer does not do on the account owner's behalf.
Their responsive behavior is therefore verified only by construction —
`grid-cols-1 sm:grid-cols-2 lg:grid-cols-3 xl:grid-cols-5` on the dashboard,
`flex-wrap` on every section header and toolbar, `overflow-x-auto` on the nav
row — and not by observation. **This is the one open item in REQ-022 and it
should be confirmed by the account owner at a narrow viewport before this is
considered fully verified.** TC-022-08 is marked `manual` in TEST-022 for
exactly this reason.

**Follow-ups (not blocking):**

- Dark mode was deferred in REQ-022's Out of Scope. The token set is now the
  natural seam for it: a `dark:` variant per token rather than per component.
- Finding 7's bundle size.
