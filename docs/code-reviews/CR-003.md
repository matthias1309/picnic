## Summary

Code review for REQ-003 implementation: a read-only REST API exposing
receipts (paginated, with date-range filtering), a single receipt with its
line items, the product catalog with purchase counts, and per-product price
history — built on the normalized data from REQ-002.

**Scope:**
- `backend/schemas.py` — new Pydantic response models: `ReceiptSummary`,
  `PaginatedReceipts`, `ReceiptItemOut`, `ReceiptDetail`, `ProductOut`,
  `PriceHistoryPoint`, `ProductPriceHistory`
- `backend/api/dependencies.py` — new, re-exports `get_db`
- `backend/api/routes.py` — new `api_router` with
  `GET /api/receipts`, `GET /api/receipts/{id}`, `GET /api/products`,
  `GET /api/products/{id}/price-history`
- `backend/services/receipt_service.py` — new query functions:
  `list_receipts`, `get_receipt_with_items`, `list_products`,
  `get_product_with_price_history`
- `backend/main.py` — mounts `api_router` under the existing `/picnic`
  router (`/picnic/api/...`); fixed a pre-existing bug where
  `LOG_LEVEL=debug` (lowercase, from `.env`) crashed `logging.basicConfig`
- `backend/tests/test_api.py` — 10 integration tests (TC-003-01..10)
- `backend/tests/conftest.py` — new `client` fixture (FastAPI `TestClient`
  with `get_db` overridden to the `db_session` fixture); `db_session`'s
  engine now uses `StaticPool` + `check_same_thread=False` so the in-memory
  SQLite database is shared with the TestClient's request thread
- `requirements.txt` — added `httpx` (required by `fastapi.testclient.TestClient`)

**Test Results:**
- 32/32 tests passing (22 pre-existing + 10 new)
- All TC-IDs documented (TC-003-01 through TC-003-10)
- 100% line coverage on `api/routes.py`, `api/dependencies.py`, `schemas.py`;
  99% on `receipt_service.py` (exceeds the 80% target from TEST-003)
- `ruff check` and `ruff format --check` pass on `backend/`

## Findings

No blockers or majors found.

| # | Severity | File / Line | Description |
|---|----------|-------------|-------------|
| 1 | minor | `backend/main.py` | Fixed pre-existing bug: `logging.basicConfig(level=settings.log_level)` raised `ValueError` because `.env` sets `LOG_LEVEL=debug` (lowercase) while Python's `logging` module requires uppercase level names. Changed to `settings.log_level.upper()`. This was previously latent because `backend.main` was never imported by the test suite; it is now imported transitively via the new `client` fixture. |
| 2 | info | `backend/tests/conftest.py` | The `db_session` fixture's engine now uses `StaticPool` + `check_same_thread=False` so the in-memory SQLite database is visible to both the test thread and the TestClient's request-handling thread. This only affects the test fixture, not production (`backend/database.py` already uses a file-based SQLite DB in production). |
| 3 | idea | `backend/api/routes.py` | Date-range filtering (`from_date`/`to_date`) uses `func.date(Receipt.received_date)`, which relies on SQLite's `date()` function. Acceptable for the SQLite-only MVP (CLAUDE.md); would need revisiting if the database backend ever changes. |

These are not bugs — noted for future iterations.

### Reasoning

The implementation satisfies all acceptance criteria of REQ-003:
- ✅ AC-003-01: `GET /picnic/api/receipts` returns a paginated list sorted by
  `received_date` descending, with `id`, `received_date`, `from_address`,
  `item_count`, and `total_cents` per entry
- ✅ AC-003-02: `GET /picnic/api/receipts/{id}` returns the full receipt with
  items (`product_name`, `quantity`, `unit_price_cents`, `line_total_cents`),
  or 404 if not found
- ✅ AC-003-03: `GET /picnic/api/products` returns all products with `id`,
  `name`, and `purchase_count`
- ✅ AC-003-04: `GET /picnic/api/products/{id}/price-history` returns a
  time-ordered list of `{date, unit_price_cents, quantity}`, or 404 if the
  product does not exist
- ✅ AC-003-05: All responses are typed via `response_model=...` (documented
  in the OpenAPI schema); errors use FastAPI's consistent `{"detail": ...}`
  contract (404 for missing resources, 422 for invalid query params)
- ✅ AC-003-06: `limit`/`offset` pagination (default 20, max 100) and
  `from_date`/`to_date` filtering are supported and validated
