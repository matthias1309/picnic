## Findings

| # | Severity | File / Line | Description |
|---|----------|-------------|-------------|
| 1 | major | `ProductCombobox.tsx:27` | **Fixed during review.** The query was seeded once via `useState(selectedProduct?.name ?? "")`. `PriceHistory` remounts on every navigation back to Statistiken while `selectedProductId` persists in `useUiStore` — if `GET /products` had not resolved at mount, the initializer saw no product and the input stayed permanently blank next to a rendered chart. Replaced with a `draftQuery: string \| null` where `null` derives the displayed value from the current selection, so a late-arriving product list labels the input correctly. |
| 2 | minor | `ProductCombobox.tsx:31` | Suggestions capped at `MAX_SUGGESTIONS = 8`. A query matching more articles silently shows only the top eight. Accepted deliberately: ranking is by purchase count, so the cut articles are the rarely-bought ones, and an uncapped panel would reintroduce the scrolling column REQ-021 exists to remove. Narrowing the query is the intended recovery. |
| 3 | minor | `ProductCombobox.tsx` | `onMouseDown={(e) => e.preventDefault()}` on each option is load-bearing, not decoration: without it the input blurs before the click lands and the option is never selected. Kept alongside the `relatedTarget` check in `onBlur` — belt and braces, because the two cover different paths (pointer vs. focus moving into the panel). |
| 4 | nit | `product-search.ts:5` | `\p{Diacritic}` needs ES2018 regex property escapes. `tsconfig` targets ES2020 and jsdom supports it, so this is fine; noted because it is the one line here that would break under an older target. |

No blockers.

### Notes

**Verified explicitly during review:**

- AC-021-09 (no regression) holds structurally: `PriceHistory.tsx`'s diff is
  confined to the picker block and one import. `usePriceTrend`,
  `rangeToFromDate`, the range buttons, the min/max/Ø line and all four
  states are byte-identical. TC-021-13 exercises them through the new picker.
- No new network traffic. `useProducts()` is unchanged — one `GET /products`,
  cached by TanStack Query — and filtering runs over that cached array, so
  keystrokes issue no requests.
- The ranking test (TC-021-03) supplies its fixture in the reverse of the
  expected order, so it cannot pass on an unsorted pass-through. The
  diacritic test uses "Müsli"/"musli", which a `toLowerCase()`-only
  implementation fails — both assertions have real discriminating power.
- Empty query returns `[]` rather than the full list (TC-021-04). This is the
  requirement, not an oversight: dumping every article is the defect.
- `knip` reports no unused exports — `searchProducts` and `ProductCombobox`
  are both reached from production code, not just tests.

**Follow-ups (not blocking):**

- The panel is styled minimally here (plain white, grey highlight). REQ-022
  restyles it along with the rest of the UI; deliberately not polished twice.
- Multi-article comparison was raised and deferred in REQ-021's Out of Scope.
  If it is ever wanted, `ProductCombobox`'s props are the seam to widen.
