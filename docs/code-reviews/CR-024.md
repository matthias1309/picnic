## Findings

| # | Severity | File / Line | Description |
|---|----------|-------------|-------------|
| 1 | major | `backend/services/category_service.py` | The bare `("eis", SWEETS)` keyword matched by substring, so **"Basmati Reis" and "Speiseöl" were classified as sweets**. Replaced with the specific compounds (`eiscreme`, `speiseeis`, `wassereis`, `eis am stiel`). Fixed in `392edb0`. |
| 2 | major | `backend/services/category_service.py` | Fruit keywords preceded the rules for compounds that begin with a fruit name: **"Apfelsaft" was fruit rather than a beverage**, "Erdbeerjoghurt" fruit rather than dairy, "Erdbeermarmelade" fruit rather than pantry. Added a compound group ahead of the fruit block. Fixed in `392edb0`. |
| 3 | minor | `backend/api/routes.py` | `purchase_count=len(product.receipt_items)` loaded every line item of a product through the relationship just to size the list. Replaced with `receipt_service.count_product_purchases`, a COUNT query. Fixed in `392edb0`. |
| 4 | nit | `frontend/src/lib/chart-theme.ts` | `CATEGORY_COLORS` was typed `Record<string, string>`, which would accept a typo'd key silently. Narrowed to `Record<CategoryKey \| "uncategorized", string>`. Fixed in `392edb0`. |
| 5 | open | `backend/services/category_service.py` | Rule *coverage* against the real catalogue is unknown — the keywords were written against typical German product names, not the production database. Not fixable before the first backfill run; see Notes. |

Findings 1 and 2 are the same class of defect that TC-024-04 exists to catch;
the test simply did not yet contain those cases. All five cases are now pinned
there as regressions, so reordering `CATEGORY_RULES` breaks the suite.

Neither defect was visible from the test suite alone — both surfaced from
running `categorize` over a list of realistic German product names during the
review. That check is worth repeating whenever the rule table is extended.
