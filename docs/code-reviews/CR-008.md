## Summary

Bugfix for `backend/imap/parser.py`: `ReceiptParser._extract_prices` failed to
find any price rows when the price `<table>`'s `<tr>` elements were wrapped in
an implicit `<tbody>` — as Gmail does when forwarding a "Dein Bon" email. This
caused every item on forwarded receipts to be stored with
`unit_price_cents = 0` and `line_total_cents = 0`, even though the receipt
itself, item names, and quantities were extracted correctly.

**Scope:**
- `backend/imap/parser.py` — new `ReceiptParser._direct_rows` helper;
  `_extract_prices` now uses it instead of `find_all("tr", recursive=False)`
- `backend/tests/test_parser.py` — 2 new unit tests (TC-008-01, TC-008-02)
- `backend/tests/conftest.py` — new `picnic_receipt_forwarded_html` fixture
- `backend/tests/fixtures/picnic_receipt_forwarded.html` — new fixture
  reproducing Gmail's `<tbody>`-wrapped invoice markup

**Test Results:**
- 68/68 tests passing (66 pre-existing + 2 new)
- `ruff check backend/` and `ruff format --check backend/` pass
