# CR-018 — Receipt List and Detail Show the Effective (Delivery) Date

**Status:** approved

## Summary

Fixes a display bug found while investigating a user report of "no receipts
that old" for a 0€ price-history point. `GET /receipts` and
`GET /receipts/{id}` only exposed `received_date`, and the UI displayed that
field — but for every receipt bulk-reprocessed on 2026-06-16/17 (see
`learnings.md`), `received_date` holds the *reprocessing* timestamp, not the
real delivery date, so April/May receipts all displayed as "16.6." or
"17.6.2026". `Receipt.effective_date` (`coalesce(delivery_date,
received_date)`) already drives sort order and was already correct — it just
wasn't exposed. Fix: add `effective_date` to `ReceiptSummary` and
`ReceiptDetail` (`backend/schemas.py`, `backend/api/routes.py`), and switch
`ReceiptList.tsx` / `ReceiptDetail.tsx` to render it instead of
`received_date`. `received_date` is kept on both schemas (unchanged
meaning, still useful). No schema migration, no new dependency.
