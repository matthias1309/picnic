## Summary

Code review for REQ-002 implementation: parsing Picnic "Dein Bon" invoice
emails into structured line items, a product catalog, and a denormalized
price-history table, plus a scheduled task that runs the parser on pending
receipts.

**Scope:**
- `backend/imap/parser.py` — `ReceiptParser` (`extract_html`, `parse`,
  price/total extraction, `ParseError`, `ParsedItem`, `ParsedReceipt`)
- `backend/models.py` — new `Product`, `ReceiptItem`, `PriceHistory` models
  and `Receipt.items` relationship
- `backend/services/receipt_service.py` — `parse_pending_receipts`,
  `_store_parsed_receipt`, `_get_or_create_product`, `_reconcile_total`,
  `ParseSummary`
- `backend/config.py` — `parse_interval` setting
- `backend/main.py` — `parse_receipts_task` + APScheduler job registration
- `backend/tests/test_parser.py` — 6 unit tests (TC-002-01..06)
- `backend/tests/test_services.py` — 5 integration tests (TC-002-07..11)
- `backend/tests/conftest.py` — `picnic_receipt_html`,
  `picnic_receipt_malformed_html`, `make_raw_email` fixtures
- `backend/tests/fixtures/picnic_receipt.html`,
  `backend/tests/fixtures/picnic_receipt_malformed.html`

## Decision

### Reasoning

The implementation satisfies the in-scope acceptance criteria of REQ-002:
- ✅ AC-002-01: Line items (name, quantity, unit price, line total) are
  extracted, including promotions (percentage discount, "X+Y gratis",
  "jetzt X€")
- ✅ AC-002-02: Products are matched/created by exact name
  (`_get_or_create_product`)
- ✅ AC-002-03: A `price_history` row is recorded per item per receipt
- ✅ AC-002-04: `parse_pending_receipts` only processes `processed == False`
  receipts and marks them processed afterwards (idempotent; no-op when
  nothing is pending)
- ✅ AC-002-05: Malformed receipts raise `ParseError`, are logged, and do
  not affect other receipts in the same run
- ✅ AC-002-06: The stated total is extracted where present and reconciled
  against the computed sum, with a warning logged on mismatch
