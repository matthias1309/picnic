## Summary

Fixes the production duplication of receipt 22 (34 `receipt_items` instead of
17). Root cause: `gunicorn --workers 2` runs one `BackgroundScheduler` per
worker (`backend/main.py`'s `lifespan()`), so two uncoordinated schedulers can
both call `parse_pending_receipts()` for the same still-pending receipt before
either commits, and `_store_parsed_receipt()` had no guard against being
called twice for one receipt. Fix: an atomic claim
(`UPDATE receipts SET processed=1 WHERE id=? AND processed=0`, checked via
`rowcount`) in `backend/services/receipt_service.py`, executed before parsing.
Single file changed, no schema/dependency changes. Production data for
receipt 22 was already corrected manually (17 duplicate `receipt_items` +
`price_history` rows removed after cross-checking the raw source email;
backup taken first).
