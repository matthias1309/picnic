# CR-009 — Delete a Receipt

**Status:** approved
**Created:** 2026-06-15
**Reviewer:** Claude Code

## Summary

Adds the ability to delete an individual receipt from the receipt detail page
at `/picnic-frontend/receipts/{id}`. Backend: new
`DELETE /picnic/api/receipts/{receipt_id}` endpoint (mounted under the
existing authenticated `api_router`) and `receipt_service.delete_receipt`,
which removes the `Receipt`, its `ReceiptItem` rows (via existing cascade),
and its `PriceHistory` rows (explicit cleanup). Frontend: a "Delete receipt"
button on `ReceiptDetail.tsx` that confirms via `window.confirm`, calls the
new endpoint via `useDeleteReceipt`, invalidates the receipts query cache, and
navigates back to `/receipts`.

### Notes

- `PriceHistory` rows are deleted explicitly because they have no ORM
  relationship or DB cascade back to `Receipt` (see ARCH-009 Key Decision 2).
  If a future migration adds `ON DELETE CASCADE` at the DB level, this
  explicit cleanup becomes redundant but remains harmless.
- Orphaned `Product` rows (zero `receipt_items` after a deletion) are
  intentionally left in place — out of scope per REQ-009.
