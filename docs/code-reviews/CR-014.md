## Summary

Feature: date a receipt by the delivery date stated in the invoice body
("… Lieferung von Montag 15 Juni 2026") instead of the email's delivery
timestamp, so a re-sent / re-delivered older invoice is placed correctly in
time. The email `Date` header is retained as metadata and used as a fallback.

**Scope:**
- `backend/imap/parser.py` — `ParsedReceipt.delivery_date`;
  `_extract_delivery_date` matches the German delivery sentence tolerantly and
  maps German month names; unknown month / out-of-range date returns `None`
  (best-effort, never raises).
- `backend/models.py` — new nullable `Receipt.delivery_date` column and an
  `effective_date` hybrid (`coalesce(delivery_date, received_date)`) usable in
  Python and SQL.
- `backend/services/receipt_service.py` — persist `delivery_date`; date
  `PriceHistory` and list/filter by `effective_date`.
- `backend/services/stats_service.py` — week/month aggregation and date filters
  use `effective_date`.
- `backend/tests/fixtures/picnic_receipt_current.html` — adds a delivery
  sentence.
- Tests: TC-014-01/02/03 (parser, incl. real-email regression), TC-014-04/05
  (service), TC-014-06 (stats).

**Test Results:**
- 109/109 backend tests pass (18 new, written first and failing before code).
- `ruff check` and `ruff format --check` clean.
