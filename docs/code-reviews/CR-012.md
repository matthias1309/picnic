## Summary

Bugfix for `backend/imap/parser.py`. A newly received Picnic invoice failed to
parse (`ParseError: No item rows found in invoice HTML`) and stored no articles.
Two root causes, both reproduced against the raw email:

1. The exact CSS selector `td[style*="border-bottom:1px solid #ebebeb"]` no
   longer matched, because Picnic's current template renders the declaration as
   `border-bottom: 1px solid #EBEBEB` (extra space, uppercase hex).
2. After fixing (1), the `Pfand` / `Lieferadresse` summary blocks share the same
   border style but have no product image, and would make `_parse_item_row`
   raise.

**Scope:**
- `backend/imap/parser.py` — new `_normalize_style` helper; `parse()` selects
  item rows by normalized (whitespace/case-insensitive) style **and** requires a
  product `img[alt]`.
- `backend/tests/test_parser.py` — TC-012-01, TC-012-02.
- `backend/tests/conftest.py` — new `picnic_receipt_current_html` fixture.
- `backend/tests/fixtures/picnic_receipt_current.html` — new anonymized fixture
  in the current format with a Pfand summary row.

**Test Results:**
- 90/90 backend tests passing.
- `ruff check backend/` and `ruff format --check backend/` pass.
