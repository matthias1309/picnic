# REQ-017 — Budget History (Last 12 Months)

**Status:** draft
**Created:** 2026-07-10
**Traced by:** ARCH-017, TEST-017

## User Story

As a user tracking my Picnic grocery spending,
I want to see budget-vs-spend for each of the last 12 months on the home dashboard, not just the current month,
in order to review my spending pattern and budget adherence over time.

## Acceptance Criteria

### AC-017-01: Historical budget boxes are shown below the current month

```gherkin
Given the home dashboard is opened
When the page has loaded
Then a budget box for the current month is shown (as today)
And a budget box is shown for each of the preceding 12 months, ordered most recent first
```

### AC-017-02: Historical boxes reuse the current box's visual style

```gherkin
Given a historical month's spend exceeds its budget
When its budget box is rendered
Then it uses the same over-budget visual style (color, "Over budget by" text) as the current month's box
And when spend is within budget, it uses the same under-budget style and "Remaining" text
```

### AC-017-03: Historical boxes are read-only

```gherkin
Given a historical month's budget box is rendered
When the user looks for an "Edit budget" control on it
Then no edit control is present
And only the current month's box offers "Edit budget"
```

## Notes

- The monthly budget amount is a single global setting (not stored per historical month), so every
  box — current and historical — displays the same configured `budget_cents` value against that
  month's actual `spent_cents`. This is a known limitation: historical boxes show "current budget
  applied retroactively," not what the budget target actually was at that time. Acceptable for this
  story; a per-month budget history table would be a separate future story.
- No backend changes are required: `GET /api/stats/budget?month=YYYY-MM` already accepts any month
  and computes `spent_cents` correctly per month via `Receipt.effective_date`.
- "Last 12 months" excludes the current month (which already has its own editable box), i.e. 12
  additional read-only boxes.
