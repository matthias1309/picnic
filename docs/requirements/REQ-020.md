# REQ-020 — German User Interface

**Status:** approved
**Created:** 2026-08-26
**Traced by:** ARCH-020, TEST-020

## User Story

As the **account owner**,
I want **the entire user interface to be in German**,
in order to **read my grocery spending in my own language instead of
switching mentally between a German receipt and an English dashboard**.

## Context

The app parses German Picnic invoices (`Gesamtbetrag`, `Bestellnr`,
`Lieferadresse`) and already formats every number and date with the `de-DE`
locale (`lib/format.ts`, `toLocaleDateString("de-DE")`). Only the UI chrome —
navigation, headings, buttons, empty states and error messages — is still
English, which makes the app read as half-translated:

- Navigation: `Home` / `Stats` / `Receipts`, `Logout`
- Dashboard cards: `Total spend`, `Distinct products`, `Average basket`, …
- Receipt detail already mixes both: the heading says
  `Receipt from 15.4.2026` directly above a `Bestellnr 209-521-1175` group.
- Budget cards render the raw API month key (`2026-08`) rather than a
  readable German month.

The app is single-user and German-only. This requirement is about writing the
UI in German, not about introducing a translation framework — see ARCH-020
for why no i18n library is added.

## Acceptance Criteria

### AC-020-01: Navigation and session controls are German

```gherkin
Given the user is logged in
When the user looks at the header navigation
Then the links read "Übersicht", "Statistiken" and "Kassenbons"
And the session button reads "Abmelden"
```

### AC-020-02: The login screen is German

```gherkin
Given the user is not logged in
When the login screen is shown
Then the fields are labelled "Benutzername" and "Passwort"
And the submit button reads "Anmelden"
And a failed login reports "Benutzername oder Passwort ist falsch."
```

### AC-020-03: Dashboard summary cards are German

```gherkin
Given summary statistics are available
When the user opens the dashboard
Then the cards are labelled "Gesamtausgaben", "Kassenbons", "Verschiedene
  Artikel", "Durchschnittlicher Einkauf" and "Ausgaben diesen Monat"
```

### AC-020-04: Statistics view is German

```gherkin
Given purchase data exists
When the user opens the statistics view
Then the headings read "Ausgaben im Zeitverlauf", "Meistgekaufte Artikel"
  and "Preisverlauf"
And the aggregation buttons read "Woche" and "Monat"
And the price-range buttons read "3 Mon.", "6 Mon.", "12 Mon." and "Gesamt"
And the price summary is labelled "Min.", "Max." and "Ø"
```

### AC-020-05: Receipt list and detail are German

```gherkin
Given receipts exist
When the user opens the receipts list
Then an entry's item count reads "12 Artikel"
And the pager buttons read "Zurück" and "Weiter"
And the pager position reads "1–3 von 3"
When the user opens a receipt
Then the heading reads "Kassenbon vom 15.4.2026"
And the delete button reads "Kassenbon löschen"
And the sum line reads "Gesamt: 12,34 €"
```

### AC-020-06: Budget cards are German and show a readable month

```gherkin
Given a budget of 300,00 € for the API month key "2026-08" with 350,00 €
  spent
When the user views the budget card
Then the card header reads "Budget für August 2026", not "Budget for 2026-08"
And the over-budget line reads "50,00 € über Budget"
And a card within budget reads "Verbleibend: …" instead
And the edit control reads "Budget bearbeiten", with "Speichern" and
  "Abbrechen" while editing
```

### AC-020-07: Loading, empty and error states are German

```gherkin
Given any view whose data fails to load
When the error state is rendered
Then its message is German and its retry button reads "Erneut versuchen"
Given any view whose data is empty
Then its empty-state message is German
And the loading spinner is announced to screen readers as "Lädt"
```

### AC-020-08: The document declares German

```gherkin
Given the user opens the app
When the browser inspects the document
Then the <html> element carries lang="de"
And the browser tab title is "Picnic Ausgaben-Tracker"
```

### AC-020-09: No behavioral regression

```gherkin
Given the existing frontend test suite
When the translation is applied
Then routing, data fetching, pagination, budget editing and receipt deletion
  behave exactly as before — only the rendered text changes
```

## Notes

**Out of Scope:**
- Any i18n/translation framework or a language switcher. The app is
  German-only; see ARCH-020.
- Backend response text, log messages, API field names, and all code
  identifiers/comments — CLAUDE.md requires the repository itself to stay
  English. This REQ covers rendered UI text only.
- The product name strings themselves — they come from Picnic and are
  already German.
