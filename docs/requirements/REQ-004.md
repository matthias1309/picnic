# REQ-004 — Statistics and Spending Insights

**Status:** draft  
**Created:** 2026-06-13  
**Traced by:** ARCH-004, TEST-004

## User Story

As a **single user tracking my Picnic purchases**,  
I want to **see aggregated spending statistics and price trends**,  
in order to **understand my grocery spending and how prices change over time**.

## Context

Building on the parsed data (REQ-002) and the data API (REQ-003), REQ-004 adds
aggregation logic and dedicated statistics endpoints. Calculations live in
`backend/services/stats_service.py` and are exposed via `/api/stats/*`.

## Acceptance Criteria

### AC-004-01: Spending over time

```gherkin
Given parsed receipts span multiple months
When the client requests GET /api/stats/spending?granularity=month
Then total spending is returned grouped by the requested period (week/month)
And each bucket includes the period label and total amount
And a date range can be supplied to bound the result
```

### AC-004-02: Top purchased items

```gherkin
Given multiple receipts with repeated products
When the client requests GET /api/stats/top-items?limit=10
Then the most frequently bought products are returned
And each entry includes product name, total quantity, and total spend
And results are ranked descending
```

### AC-004-03: Price trend for a product

```gherkin
Given a product has price_history across several receipts
When the client requests GET /api/stats/price-trend/{product_id}
Then a time series of prices is returned
And it includes min, max, and average price over the selected range
```

### AC-004-04: Budget tracking

```gherkin
Given a monthly budget value is configured
When the client requests GET /api/stats/budget?month=2026-06
Then the configured budget, actual spend, and remaining/over amount are returned
So that the user can see whether they are within budget
```

### AC-004-05: Summary overview

```gherkin
Given parsed data exists
When the client requests GET /api/stats/summary
Then headline figures are returned: total spend, receipt count,
     distinct product count, average basket value, and current-month spend
```

### AC-004-06: Empty-data handling

```gherkin
Given no parsed receipts exist yet
When any statistics endpoint is called
Then a well-formed empty/zeroed result is returned (not an error)
So that the dashboard renders gracefully on first run
```

## Notes

**Implementation approach:**
- Aggregations in `backend/services/stats_service.py`, called by thin routes.
- Prefer SQL-level aggregation (GROUP BY) via SQLAlchemy over in-Python loops.
- Use `price_history` (denormalized, per CLAUDE.md) for efficient trend queries.
- Budget value sourced from config/.env for MVP (no per-user storage yet).
- Amounts in integer cents internally; formatting decided in REQ-003/REQ-005.

**Out of Scope (Phase 2+):**
- ML-based recommendations, clustering, anomaly detection.
- Per-category budgets or multiple budgets.
- Forecasting / predicted spend.
- Export (CSV/PDF) of statistics → Phase 2+.

**Testing Strategy:**
- Unit tests on stats_service with deterministic seeded data sets.
- Verify grouping boundaries (week/month edges), ranking order, averages.
- Edge cases: empty data, single receipt, ties in top-items ranking.
- See TEST-004 (to be created) for detailed test cases.

**Questions / Decisions Pending:**
- Where does the budget value live for MVP — .env, config, or a settings table?
- Week definition: ISO weeks (Mon–Sun)?
- Should price trends be per unit price or per line total?
