# REQ-010 — Filter Ingested Emails by Subject

**Status:** approved
**Created:** 2026-06-15
**Traced by:** ARCH-010, TEST-010

## User Story

As the **account owner**,
I want **the polling task to only ingest emails whose subject contains "Dein Bon"**,
in order to **avoid storing unrelated Picnic emails (newsletters, delivery
notifications, order confirmations, etc.) as receipts that then fail
parsing and clutter the receipt list**.

## Context

REQ-001/ARCH-001 introduced IMAP polling via `IMAPClient.fetch_new_emails`,
which currently runs `search(None, "ALL")` — every email in the mailbox is
fetched and, if its `Message-ID` is not yet known, stored as a `Receipt`
(`backend/main.py:58-99`). REQ-002 then attempts to parse every unprocessed
`Receipt` and marks it `failed` if the invoice table cannot be found
(`backend/services/receipt_service.py:46-49`).

Picnic sends several types of emails to the same mailbox (order
confirmations, delivery updates, newsletters, "Dein Bon" invoices). Only
emails with "Dein Bon" in the subject contain the itemized invoice table
this app needs. All other emails are currently stored as `Receipt` rows,
permanently fail parsing, and clutter the receipt list and logs.

This REQ restricts ingestion to emails whose subject contains "Dein Bon",
filtered at the IMAP level so non-matching emails are never downloaded or
stored.

## Acceptance Criteria

### AC-010-01: Polling only fetches emails with "Dein Bon" in the subject

```gherkin
Given the IMAP mailbox contains emails with a variety of subjects
When the polling task runs
Then only emails whose subject contains "Dein Bon" are fetched
And emails with other subjects are not downloaded or stored as receipts
```

### AC-010-02: Subject match is case-insensitive and substring-based

```gherkin
Given an email with subject "Dein Bon von Picnic - Bestellung 102-651-1311"
When the polling task runs
Then the email is fetched and stored as a Receipt (per AC-001-02)
```

```gherkin
Given an email with subject "dein bon von picnic"
When the polling task runs
Then the email is fetched and stored as a Receipt
```

### AC-010-03: Non-matching emails remain untouched in the mailbox

```gherkin
Given the mailbox contains an email with subject "Deine Bestellung ist auf dem Weg"
When the polling task runs
Then no Receipt row is created for that email
And the email is left in the mailbox unchanged (no flags set, not deleted)
```

### AC-010-04: Subject filter is configurable with a sensible default

```gherkin
Given the IMAP_SUBJECT_FILTER setting is not explicitly configured
When the polling task builds its IMAP search query
Then it defaults to filtering on the subject "Dein Bon"
```

```gherkin
Given the IMAP_SUBJECT_FILTER setting is set to a custom value
When the polling task builds its IMAP search query
Then it filters on the configured value instead of the default
```

## Notes

**Implementation approach:**
- Use IMAP `SEARCH SUBJECT "<filter>"` instead of `SEARCH ALL` in
  `IMAPClient.fetch_new_emails` (`backend/imap/client.py:100`). The IMAP
  `SUBJECT` search key performs a case-insensitive substring match per
  RFC 3501, so AC-010-02 requires no additional client-side filtering.
- Add `imap_subject_filter: str = "Dein Bon"` to `Settings`
  (`backend/config.py`).

**Out of Scope:**
- Cleaning up `Receipt` rows that were already stored from non-matching
  emails before this filter existed — a separate manual/maintenance task if
  needed.
- Filtering by sender address — subject filtering is sufficient to identify
  "Dein Bon" invoices.
- Configurable filtering via the UI — `.env` setting only, consistent with
  other IMAP configuration (REQ-001).
