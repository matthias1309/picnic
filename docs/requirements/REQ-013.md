# REQ-013 — Group Receipt Line Items by Picnic Order Number

**Status:** approved
**Created:** 2026-06-16
**Traced by:** ARCH-013, TEST-013

## User Story

As the **account owner**,
I want **each parsed line item to be associated with the Picnic order number it
belongs to**,
in order to **see, on a receipt, which articles came from which order** (a
single "Dein Bon" email can bundle several separate orders).

## Context

A Picnic "Dein Bon" email groups its articles into sections, each introduced by
a header like:

```
Hinzugefügt am Sonntag 14 Juni
Bestellnr 209-521-1175
```

All item rows below such a header, until the next header, belong to that order.
A single email frequently contains several orders (e.g. `209-521-1175` and
`204-701-1435`). Today `ReceiptParser` flattens all rows into one list and
discards the order numbers, so items from different orders cannot be told apart
once stored.

## Acceptance Criteria

### AC-013-01: Parser assigns each item its order number

```gherkin
Given an invoice email with two "Bestellnr" sections and items under each
When ReceiptParser.parse() is called
Then each ParsedItem carries the order_number of the section it appears in
```

### AC-013-02: Items before any order header have no order number

```gherkin
Given an invoice whose item rows appear before any "Bestellnr" header
When ReceiptParser.parse() is called
Then those items have order_number = None (rather than failing to parse)
```

### AC-013-03: Order number is persisted with each receipt item

```gherkin
Given a parsed receipt whose items carry order numbers
When the receipt is stored
Then each receipt_items row records its order_number
```

### AC-013-04: API exposes the order number per item

```gherkin
Given a stored receipt whose items have order numbers
When the receipt detail is requested from the API
Then each item in the response includes its order_number
```

### AC-013-05: Receipt detail groups items by order number in the UI

```gherkin
Given a receipt whose items belong to more than one order number
When the receipt detail view is rendered
Then items are grouped under their order number heading
And a receipt with a single (or no) order number renders as one group
```

## Notes

**Implementation approach:**
- `ParsedItem` gains an `order_number: str | None` field. The parser reads the
  nearest preceding `Bestellnr NNN-NNN-NNNN` text for each item row.
- `ReceiptItem` gains a nullable `order_number` column (existing rows and
  emails without order numbers stay `NULL`). **DB schema change — reviewed by a
  human before the production DB is migrated (CLAUDE.md).**
- `ReceiptItemOut` schema and the receipt-detail endpoint expose `order_number`.
- `ReceiptDetail.tsx` groups items by `order_number`.

**Out of Scope:**
- Statistics / charts broken down by order number (Phase 2+).
- Backfilling order numbers onto already-parsed receipts (manual re-parse,
  same as REQ-008/REQ-012).
- A dedicated "orders" table or order-level totals — items reference the order
  number as a plain string for the MVP.

**Testing Strategy:**
- Parser unit tests on `picnic_receipt_current.html` (two orders) and the
  existing `picnic_receipt.html` (single `Bestellnr 102-651-1311`).
- Service test asserting `order_number` is persisted.
- Frontend test asserting items render grouped by order number.
- See TEST-013.
