# REQ-011 — Configure Monthly Budget

**Status:** draft
**Created:** 2026-06-15
**Traced by:** ARCH-011, TEST-011

## User Story

As the **account owner**,
I want **to set and change my monthly budget directly from the dashboard**,
in order to **track my spending against a budget that matches my actual
situation, without editing server configuration or `.env` files**.

## Context

REQ-004/AC-004-04 introduced `GET /api/stats/budget?month=YYYY-MM`, and
REQ-005/AC-005-05 added `BudgetWidget.tsx` on the home page
(`https://matt-maxx.de/picnic-frontend/`), which displays "Budget for
2026-06" with spend vs. budget. The budget value (`budget_cents`) currently
comes from the read-only `MONTHLY_BUDGET_CENTS` setting in
`backend/config.py` / `.env` (`settings.monthly_budget_cents`), which the
user cannot change from the UI — only a developer editing `.env` and
restarting the backend can change it.

This REQ adds the ability to view and update the configured monthly budget
from the `BudgetWidget`, persisting the value in the database so it survives
restarts and is editable without server access.

## Acceptance Criteria

### AC-011-01: Edit control is visible on the budget widget

```gherkin
Given the user is viewing the budget widget on the home page
When the widget has loaded
Then an "Edit budget" control is visible
```

### AC-011-02: Editing opens a form pre-filled with the current budget

```gherkin
Given the budget widget shows a configured budget of 300.00 €
When the user clicks "Edit budget"
Then an input field is shown, pre-filled with "300.00"
And "Save" and "Cancel" controls are shown
```

### AC-011-03: Saving updates the budget and is reflected immediately

```gherkin
Given the user has opened the budget edit form
When they enter "350" and click "Save"
Then a PUT request is sent to /api/settings/budget with monthly_budget_cents = 35000
And the widget closes the edit form
And the widget displays the updated budget (350,00 €) without a page reload
```

### AC-011-04: Cancelling discards changes

```gherkin
Given the user has opened the budget edit form and changed the value
When they click "Cancel"
Then no request is sent
And the widget shows the previously configured budget, unchanged
```

### AC-011-05: Negative or invalid input is rejected

```gherkin
Given the user has opened the budget edit form
When they enter "-10" and click "Save"
Then no request is sent
And a validation message is shown
And the budget remains unchanged

Given the client sends PUT /api/settings/budget with monthly_budget_cents = -1
Then a 422 response is returned
And the stored budget remains unchanged
```

### AC-011-06: Configured budget persists and applies to subsequent requests

```gherkin
Given the user has set the monthly budget to 35000 cents via PUT /api/settings/budget
When the client requests GET /api/stats/budget?month=2026-06 (or any other month)
Then budget_cents is 35000
And the value persists across application restarts (stored in the database,
  not in-memory)
```

## Notes

**Implementation approach:**
- Persist the configured budget in a new database table (single row),
  read/written via a small service module.
- `GET /api/stats/budget` reads the persisted value; if no value has been
  configured yet, it falls back to the existing `MONTHLY_BUDGET_CENTS` `.env`
  default (AC-004-04 remains backward compatible).
- New endpoint `PUT /api/settings/budget` updates the persisted value.
  Mounted under the existing authenticated `api_router` (REQ-006,
  AC-006-04) — same as the other mutating endpoint (`DELETE /receipts/{id}`,
  REQ-009).
- `BudgetWidget.tsx` gains inline edit mode (toggle button, input, save/cancel),
  reusing the existing TanStack Query cache (`["stats", "budget", month]`).

**Out of Scope:**
- Per-category budgets or multiple budgets — still out of scope per REQ-004.
- Per-month budgets (configuring a different value for each month) — a
  single recurring monthly budget value is configured, matching the current
  "Budget for {month}" display, which already reuses one value for any
  queried month.
- A dedicated Settings page — the edit control lives directly in
  `BudgetWidget`, consistent with ARCH-005 Key Decision 6 (no Settings page
  without a concrete requirement).
- Currency selection / localization beyond the existing EUR formatting
  (`formatCents`).
