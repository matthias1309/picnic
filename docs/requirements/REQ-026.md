# REQ-026 — Split "Trockenware" into Finer Categories

**Status:** draft
**Created:** 2026-10-10
**Traced by:** ARCH-026, TEST-026, CR-026

## User Story

As the **account owner**,
I want **the broad "Trockenware" category split into pasta & grains, breakfast,
baking, condiments, canned goods and snacks**,
in order to **see which kind of shelf-stable groceries my money goes to, instead
of one bucket that mixes noodles, spices, jam and crisps**.

## Context

REQ-024 introduced a fixed set of 14 categories. `pantry` ("Trockenware") turned
out to be the catch-all for everything shelf-stable: about 20 keyword rules from
five unrelated groups (pasta, baking, spices, breakfast, canned goods) end up in
one bucket, which makes it the least informative bar in the
"Ausgaben nach Kategorie" chart.

While reviewing the `pantry` rules, several ordering defects in
`CATEGORY_RULES` were found. They are fixed as part of this REQ because the
split touches exactly these rules:

- "Passierte Tomaten" never reaches its rule: `tomate` (vegetables) is listed
  earlier and wins.
- Short keywords match inside unrelated names: `öl` in "Ölsardinen" and
  "Kölln Haferflocken", `reis` in "Preiselbeeren" and "Reiswaffeln", `salz` in
  "Salzstangen".
- Several keywords appear twice (e.g. `marmelade`, `saft`, `joghurt`); the
  second occurrence can never match and is dead code.
- A check of every rule against the rule list (2026-10-10) found four rules
  that can never fire because an earlier keyword is contained in them:
  `nektarine` → `nektar` (beverages), `wassereis` → `wasser` (beverages),
  `zahnpasta` → `pasta` (pantry), `passierte tomaten` → `tomate`
  (vegetables). AC-026-08 makes this class of defect a test failure.

## Notes

**Implementation approach:**
- `CategoryKey` gains `GRAINS`, `BAKING`, `BREAKFAST`, `CONDIMENTS`, `CANNED`
  and `SNACKS`. `PANTRY` stays, relabelled to "Sonstige Trockenware". This is
  deliberate: it keeps existing manual assignments valid, so **no data
  migration is needed**. The column `products.category_key` is a free
  `VARCHAR(32)`, so new keys need no schema change either.
- Products in `pantry` that the backfill does not move (manual assignments,
  products no new rule matches) stay where they are. The user can move manual
  ones by hand in the article list.
- Proposed keyword rules per category (final list and order in ARCH-026):

  | Category | Keywords |
  |---|---|
  | `grains` | nudel, pasta, spaghetti, penne, fusilli, tortellini (dry), reis, couscous, bulgur, quinoa, polenta, grieß, linsen, kichererbsen |
  | `breakfast` | haferflocken, müsli, cornflakes, granola, honig, marmelade, konfitüre, nuss-nougat, erdnussbutter, preiselbeer |
  | `baking` | mehl, zucker, backpulver, hefe, vanillezucker, speisestärke, kakao (baking) |
  | `condiments` | salz, pfeffer, gewürz, öl, essig, ketchup, senf, mayonnaise, pesto, sojasauce, brühe, tomatenmark |
  | `canned` | passierte tomaten, gehackte tomaten, konserve, dose, mais, kidneybohnen, bohnen, kokosmilch |
  | `snacks` | chips, salzstangen, salzbrezel, erdnüsse, nüsse, cashew, mandeln, studentenfutter, cracker, popcorn, reiswaffel |

- Ordering constraints (extending ARCH-024 Key Decision 3, covered by tests):
  - Compound names come before the general keyword they contain:
    `passierte tomaten` / `gehackte tomaten` / `tomatenmark` before `tomate`;
    `ölsardine` (fish) and `kölln` / `haferflocken` before `öl`;
    `preiselbeer`, `reiswaffel` and `milchreis` before `reis`;
    `salzstangen` / `salzbrezel` before `salz`;
    `nuss-nougat` before `nuss` and before `creme` (personal care).
  - `chips` moves from `sweets` to `snacks`.
- The duplicate keywords in `CATEGORY_RULES` are removed. A test asserts
  that every keyword appears only once.
- `CHART_COLORS` needs six more categorical colours (14 → 20) that still meet
  the contrast requirements in light and dark mode.

**Resolved questions (2026-10-10):**
- "Bohnen" is ambiguous: dried or canned beans → `canned`, but "Grüne Bohnen"
  (fresh) are vegetables. Decision: `grüne bohnen` → vegetables, listed before
  `bohnen`.
- "Kakao" can be a baking ingredient or a drink powder. Decision: `backkakao` →
  baking, any other `kakao` → beverages.

**Out of Scope:**
- AI-based category suggestions (discussed separately; would need its own REQ
  because it adds an external service).
- Sub-categories or multiple categories per product. The new categories are
  flat siblings of the existing ones; REQ-024's "exactly one category per
  product" still holds.
- Splitting other broad categories (e.g. `household`, `beverages`).
