# REQ-001 — IMAP Polling and Email Ingestion

**Status:** draft  
**Created:** 2026-06-12  
**Traced by:** ARCH-001 _(TEST-001 pending)_

## User Story

As a **system backend**,  
I want to **automatically poll Picnic emails from Uberspace IMAP and store raw invoice data**,  
in order to **build a historical database of receipts for later analysis**.

## Acceptance Criteria

### AC-001-01: IMAP credentials configuration

```gherkin
Given the FastAPI backend is running
When the user provides valid IMAP credentials (host, port, username, password)
Then the IMAP connection is established and tested
And credentials are stored securely in .env (not committed to git)
```

### AC-001-02: Periodic email polling

```gherkin
Given IMAP credentials are configured
When the polling task runs every 30 minutes (APScheduler)
Then new emails from Picnic are downloaded from INBOX
And raw email text (full MIME message) is stored in SQLite receipts table
And email Message-ID is recorded to prevent future duplicates
```

### AC-001-03: Duplicate email prevention

```gherkin
Given an email with Message-ID "abc123@picnic.app" is already in the database
When the same email arrives again in the next polling cycle
Then it is skipped and not re-processed
And a log entry records the duplicate detection
```

### AC-001-04: Error handling and resilience

```gherkin
Given IMAP connection fails temporarily (e.g. network timeout, auth error)
When the polling task encounters an error
Then the error is logged with timestamp, error details, and context
And the task continues gracefully (does not crash the background daemon)
And a retry happens in the next polling cycle (after 30 minutes)
```

## Notes

**Implementation approach:**
- Use Python `imaplib` for IMAP communication (stdlib, no extra dependency).
- Store raw email in `receipts.raw_email_text` column (TEXT field).
- Use `receipts.message_id` (unique constraint) for deduplication.
- Polling task runs via APScheduler in the FastAPI lifespan event.
- Credentials sourced from `.env` at startup (Pydantic Settings).

**Out of Scope (Phase 2+):**
- Email parsing (HTML → structured receipt data) — see REQ-002
- User interface for credential management — hardcoded `.env` for MVP
- Archive/delete old emails from IMAP
- Multiple mailboxes or IMAP accounts

**Testing Strategy:**
- Unit tests: Mock IMAP server (responses to SELECT, SEARCH, FETCH commands)
- Integration tests: Real SQLite, test message deduplication with actual email data
- See TEST-001 for detailed test cases

**Questions / Decisions Pending:**
- Should we support OAuth2 for IMAP (RFC 6750 Bearer token), or only username/password for MVP?  
  → **Decision: Username/password for MVP. OAuth2 is Phase 2+.**
- What if the email size is huge? Pagination or streaming?  
  → **Decision: Download all emails up to 50MB per email; add streaming in Phase 2 if needed.**
