# REQ-021 — Deep Links Survive Browser Reload and Back Navigation

**Status:** approved
**Created:** 2026-08-27
**Traced by:** ARCH-021, TEST-021

## User Story

As the **account owner**,
I want **a client-side route such as `/stats` to keep working when I press
reload or the browser's back button**,
in order to **use, bookmark and share deep links instead of always having to
strip the path back to the domain root before the app loads**.

## Context

The frontend is a React SPA using `BrowserRouter` (real URLs, no hash
routing), published as a static bundle into a document root served by
Uberspace's Apache (`FRONTEND_PUBLISH_DIR`, see
[scripts/deploy.sh](../../scripts/deploy.sh) and REQ-019).

When the user navigates inside the app, React Router changes the URL via the
History API — no request reaches the server, so `/stats` renders fine. On a
reload (or a back navigation that leaves the History stack entry range of the
loaded document), the browser does request `GET /stats` from Apache. Apache
resolves that against the filesystem, finds no `stats` file or directory, and
answers with its own 404 page ("Not Found — The requested URL was not found
on this server."). The bundle is never loaded, so React Router never gets a
chance to route.

The standard fix for a history-mode SPA is a server-side fallback: any
request that does not map to an existing file or directory is answered with
`index.html`. On Uberspace's Apache this is an `.htaccess` in the document
root.

`docs/DEPLOYMENT.md` (REQ-019 cutover, step 4) already instructs creating an
`.htaccess` with a single `RewriteBase /` line by hand — which contains no
fallback rule, and is deleted on every deploy anyway, because
`scripts/deploy.sh` does `rm -rf "$FRONTEND_PUBLISH_DIR"` before copying the
new build. The fallback therefore has to be produced by the deploy itself,
not by a manual one-off step.

Affects both environments (prod at the domain root, dev/staging under
`/picnic-frontend/`); the Vite dev server is unaffected, as it already serves
`index.html` for unknown paths.

## Acceptance Criteria

### AC-021-01: A deep link is answered with the SPA instead of a 404

```gherkin
Given the frontend has been published to its document root by a deploy
When Apache receives a request for a path with no matching file or directory
  (e.g. /stats)
Then it serves index.html for that path
And the SPA boots and renders the /stats route
```

### AC-021-02: Existing files are still served as themselves

```gherkin
Given the published document root contains index.html and assets/
When Apache receives a request for an existing file or directory
  (e.g. /assets/index-abc123.js)
Then that file is served unchanged, not rewritten to index.html
```

### AC-021-03: The fallback matches the host's frontend base path

```gherkin
Given a host publishes the frontend under base path <base>
  (prod: "/", dev/staging: "/picnic-frontend/")
When the deploy writes the fallback configuration
Then the rewrite is based at <base>, so both hosts fall back to their own
  index.html
```

### AC-021-04: The fallback is (re-)created by every deploy

```gherkin
Given scripts/deploy.sh wipes and recreates the publish directory on each run
When a deploy publishes a new frontend build
Then the fallback configuration is written into the publish directory again
And it replaces any stale hand-written configuration left there
```
