# REQ-005 — React Dashboard

**Status:** draft  
**Created:** 2026-06-13  
**Traced by:** ARCH-005, TEST-005

## User Story

As a **single user tracking my Picnic purchases**,  
I want to **view my receipts, price trends, and spending statistics in a web dashboard**,  
in order to **explore my grocery data visually without touching the database or API directly**.

## Context

REQ-005 is the frontend layer. It consumes the REST API (REQ-003) and statistics
endpoints (REQ-004) and renders them as a React SPA per the frontend stack in
CLAUDE.md (React 18, TypeScript, TanStack Query, Zustand, Recharts, Tailwind,
Vite). No authentication in MVP (single-user assumption).

## Acceptance Criteria

### AC-005-01: Dashboard overview page

```gherkin
Given the API is reachable
When the user opens the dashboard home page
Then headline statistics from /api/stats/summary are displayed
And loading and error states are shown while data is fetched
```

### AC-005-02: Price history chart

```gherkin
Given a product with price history is selected
When the user views the price history chart
Then a Recharts line chart renders price over time
And the time range is configurable (e.g. 3m / 6m / 12m / all)
```

### AC-005-03: Purchase statistics view

```gherkin
Given parsed data exists
When the user opens the statistics view
Then top purchased items and spending-over-time are visualized
And the user can switch the aggregation period (week/month)
```

### AC-005-04: Receipt list and detail

```gherkin
Given receipts exist
When the user opens the receipts list
Then receipts are shown paginated, sorted by date descending
And selecting a receipt shows its line items with quantities and prices
```

### AC-005-05: Budget tracking display

```gherkin
Given a budget is configured in the backend
When the user views the budget widget
Then actual spend versus budget for the current month is displayed
And an over-budget state is visually distinct
```

### AC-005-06: Server state management and resilience

```gherkin
Given the dashboard fetches data from the API
When requests are in flight, succeed, or fail
Then TanStack Query handles caching, loading, and error states
And the UI degrades gracefully (empty states, retry) without crashing
```

## Notes

**Implementation approach:**
- Vite + React + TypeScript project under `frontend/` (per CLAUDE.md structure).
- Data fetching via TanStack Query in `src/api/client.ts` and `src/hooks/`.
- Local UI state via Zustand; charts via Recharts; styling via TailwindCSS.
- Components per CLAUDE.md layout: Dashboard, Charts/PriceHistory, Charts/PurchaseStats.
- Tests with Vitest + React Testing Library.

**Out of Scope (Phase 2+):**
- Authentication / login screen.
- IMAP credential management UI (CLAUDE.md lists IMAPConfig; .env-only for MVP).
- Mobile-native app → web responsive only.
- Real-time updates / websockets → polling/refetch only.

**Testing Strategy:**
- Component tests with mocked API responses (RTL + Vitest).
- Assert loading/empty/error states and correct rendering of fetched data.
- Test chart wrappers via data-to-props mapping, not Recharts internals.
- See TEST-005 (to be created) for detailed test cases.

**Questions / Decisions (resolved in ARCH-005):**
- Routing: multi-route via React Router (`/`, `/stats`, `/receipts`, `/receipts/:id`).
- Dev frontend uses a Vite proxy to `/picnic/*` on the backend (matches the
  production reverse-proxy path), so the client always uses relative URLs.
- Theme: green for under-budget/falling price, red for over-budget/rising
  price, gray for neutral.
