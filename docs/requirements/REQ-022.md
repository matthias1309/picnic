# REQ-022 — Consistent Visual Design and Layout

**Status:** approved
**Created:** 2026-08-26
**Traced by:** ARCH-022, TEST-022

## User Story

As the **account owner**,
I want **the app to look like one designed product rather than a set of
unstyled forms**,
in order to **read my spending at a glance and enjoy using it daily**.

## Context

The UI was built screen by screen with ad-hoc Tailwind utilities, and the
seams show:

- **No shared surface.** `Dashboard` cards are `rounded-lg bg-white p-4
  shadow`, budget cards are the same but tinted, and `PurchaseStats`,
  `PriceHistory`, `ReceiptList` and `ReceiptDetail` sit directly on the page
  background with no container at all. The Statistiken page reads as loose
  text on grey.
- **No colour identity.** Everything is `gray-*` plus one hardcoded
  `#2563eb` repeated in both charts. Nothing connects the app to Picnic.
- **Weak hierarchy.** Every heading is `text-lg font-semibold`, every card
  label `text-sm text-gray-500`, so the page offers no reading order.
- **Inconsistent controls.** Buttons are declared inline at nine call sites
  with six different class combinations; the active/inactive toggle style is
  duplicated verbatim in `PriceHistory` and `PurchaseStats`.
- **Rows do not scan.** `ReceiptList` and `ReceiptDetail` lay out rows with
  `justify-between`, so columns do not line up between rows — prices land at
  a different x-position on every line.
- **Not responsive.** The header, the dashboard's `lg:grid-cols-5` and the
  chart toolbars are laid out for a wide desktop; on a phone the nav and the
  price-history toolbar crowd or overflow.
- **Budget history is a wall.** Twelve full-size budget cards render stacked
  at equal visual weight, so the current month does not stand out.

## Acceptance Criteria

### AC-022-01: Every content block sits on a shared surface

```gherkin
Given any page of the app
When it renders
Then each content block (dashboard cards, charts, lists, budget) sits in a
  card surface with consistent radius, padding, border and shadow
And no content block sits directly on the page background
```

### AC-022-02: A single design-token set defines colour and elevation

```gherkin
Given the Tailwind configuration
When a component needs a brand colour, a surface, or a border
Then it uses a named theme token
And no component contains a hardcoded hex colour
```

### AC-022-03: Charts use the theme's colours

```gherkin
Given the price-history and spending charts
When they render
Then their series, grid and axis colours come from the shared token set
And the hardcoded "#2563eb" no longer appears in either chart
```

### AC-022-04: Buttons are declared once and reused

```gherkin
Given the app's buttons
When one is rendered
Then it comes from a shared Button component with named variants
And its focus state is visible for keyboard users
```

### AC-022-05: Toggle groups share one implementation

```gherkin
Given the price-history range toggle and the spending period toggle
When they render
Then both come from the same shared toggle-group component
And the duplicated active/inactive class strings are gone
```

### AC-022-06: Tabular rows align into columns

```gherkin
Given the receipt list and a receipt's line items
When several rows render
Then quantities, unit prices and totals align vertically across rows
And numeric values are right-aligned
```

### AC-022-07: Typography establishes a clear hierarchy

```gherkin
Given any page
When it renders
Then a page-level heading is visually distinct from section headings
And section headings are distinct from body text and metric labels
```

### AC-022-08: The layout works on a phone

```gherkin
Given a 375px-wide viewport
When the user opens any page
Then no content overflows horizontally
And the navigation remains usable
And the dashboard metric cards reflow instead of shrinking to fit
```

### AC-022-09: The current month is emphasised over past months

```gherkin
Given the current month's budget and twelve past months
When the home page renders
Then the current month's card is visually dominant
And past months are presented compactly under a heading, not as twelve
  equally-weighted cards
```

### AC-022-10: Interactive elements respond to hover and focus

```gherkin
Given any button, link, receipt row or suggestion
When the user hovers it or focuses it with the keyboard
Then it shows a visible state change
```

### AC-022-11: No behavioral or textual regression

```gherkin
Given the existing test suite after REQ-020 and REQ-021
When the restyle is applied
Then every test still passes
And no German string introduced by REQ-020 changes
And no data flow, route or API call changes
```

## Notes

**Out of Scope:**
- New dependencies. No UI component library — see ARCH-022.
- Dark mode. Considered and deferred: it doubles the token surface and every
  visual test, for a single-user app that runs in daylight. Worth its own REQ
  if wanted.
- Any change to what data is shown, or to the German wording from REQ-020.
- Charting beyond colour and container — no new chart types or interactions.
