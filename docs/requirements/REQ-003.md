# REQ-003 — REST API for Receipt and Product Data

**Status:** draft  
**Created:** 2026-06-13  
**Traced by:** ARCH-003, TEST-003

## User Story

As a **frontend client**,  
I want to **read receipts, items, and products through a REST API**,  
in order to **display purchase history and feed charts in the dashboard**.

## Context

REQ-002 produces normalized data (`receipts`, `receipt_items`, `products`,
`price_history`). REQ-003 exposes that data read-only over HTTP so the React
SPA (REQ-005) can consume it. Statistics endpoints are handled separately in
REQ-004; this REQ covers raw data access and listing.

## Acceptance Criteria

### AC-003-01: List receipts

```gherkin
Given parsed receipts exist in the database
When the client requests GET /api/receipts
Then a paginated list of receipts is returned as JSON
And each entry includes id, received_date, from_address, item count, and total
And results are sorted by received_date descending by default
```

### AC-003-02: Get a single receipt with items

```gherkin
Given a receipt with id X exists
When the client requests GET /api/receipts/{X}
Then the receipt is returned with its full list of items
And each item includes product name, quantity, unit price, and line total
And a 404 is returned if the receipt does not exist
```

### AC-003-03: List products

```gherkin
Given parsed products exist
When the client requests GET /api/products
Then a list of products is returned with id and name
And optionally each product includes how many times it was purchased
```

### AC-003-04: Get product price history

```gherkin
Given a product with id Y has price_history entries
When the client requests GET /api/products/{Y}/price-history
Then a time-ordered list of (date, price, quantity) points is returned
And a 404 is returned if the product does not exist
```

### AC-003-05: Validated responses and error contract

```gherkin
Given any API endpoint is called
When the response is produced
Then it conforms to a documented Pydantic response schema
And errors return a consistent JSON error body with an appropriate HTTP status
```

### AC-003-06: Pagination and filtering

```gherkin
Given many receipts exist
When the client requests GET /api/receipts?limit=20&offset=40
Then at most 20 receipts are returned starting from offset 40
And date-range filtering (from_date, to_date) is supported
```

## Notes

**Implementation approach:**
- FastAPI routers in `backend/api/routes.py`; thin wrappers over services.
- Pydantic response schemas in `backend/schemas.py`.
- DB session injected via `backend/api/dependencies.py`.
- Read-only for MVP — no create/update/delete of receipts via API.
- Auto-generated OpenAPI docs serve as the API contract.

**Out of Scope (Phase 2+):**
- Authentication / authorization → single-user MVP (REQ notes in CLAUDE.md).
- Statistics/aggregation endpoints → see REQ-004.
- Write endpoints (manual receipt entry / corrections) → Phase 2+.
- Rate limiting and caching headers → Phase 2+.

**Testing Strategy:**
- API tests with FastAPI TestClient against in-memory SQLite seeded per test.
- Assert status codes, response schema shape, pagination, 404 paths.
- See TEST-003 (to be created) for detailed test cases.

**Questions / Decisions Pending:**
